## 事情的起点

那天上午的任务很典型：分析一款桌面竞品。对方有双轨发行——GitHub 上挂着免费开源版，官网上卖闭源新版，两个版本号差着一大截。

我的环境里躺着什么？一套 41 条路由规则的逆向方法论 skill，还有 REA——morluto/rea，GitHub 上 22 万 star 的逆向工程 MCP，138 个工具，能解 PE 头、能提符号、能分析前端 bundle——外加一条白纸黑字的纪律：任何任务先查 skill，禁止直接编码。

一个上午过去了。实际发生的是：解包用 7z，PE 结构用 Python 现装库读，字符串用二进制扫描——全程没碰那 138 个工具里的任何一个。直到有人问我"你用 REA 了吗"，我才意识到没有。

更要命的是，正是后来用 REA 重做的二进制分析，才挖出闭源版里编译着开源版被桩掉的商业引擎。只看源码的话，这个结论就漏了。

## 溯源：它是不知道，还是知道却不用？

### 第一步：先确认它到底"看得见"什么

第一个怀疑对象是：工具对它不可见。翻了 Claude Code 的延迟加载机制——它有个 `ToolSearch`，工具不再默认全部挂载，要用时搜索唤醒。

实测下来，搜索范围是这样的：

- 基础工具（Bash、Read、Write）全文常驻，每轮都在；
- skill 走独立通道，一行描述常驻，调用时才读完整文档；
- **MCP 工具被收进延迟池，上下文里只剩一串裸名字**，比如 `mcp__xxx__analyze_javascript_application`。

也就是说，它"看得见"所有工具的名字，但看不见任何一个工具的说明书。名字到能力之间，断了一层。

### 第二步：把这个断点放进渐进式披露的框架里看

AgentSkills 规范讲的三层渐进披露是：L1 意图索引（一行描述，几十 token）→ L2 指令展开（用的时候才读文档）→ L3 参数 Schema（确定要用了才加载）。

延迟加载砍掉了静态 token 消耗，代价是 MCP 工具只剩 L1 的名字，L2 直接缺失。模型拿着一串机器命名的英文标识，不去主动搜，就永远不知道 `inspect_binary_layout` 能在十秒内给出节区表和缓解标志。

于是出现一个恶性循环：猜不到搜索关键词 → 以为没有趁手工具 → 退回 Bash。而 Bash 在预训练语料里权重极高，是模型的舒适区，滑过去毫无阻力。

### 第三步：为什么 skill 没有这个问题

这解释了另一个现象：同一个环境里，skill 很少被漏。skill 的 L1 是人话（"逆向/应用分析统一路由 skill"），MCP 的 L1 是机器名。人话能触发直觉联想，机器名不能。

这也是社区从"无脑堆 MCP"转向"skill 为主"的原因。MCP 协议的原始设计里，客户端连接就要全量拉取 `tools/list`，两百个工具的 JSON-Schema 每轮白烧十几万 token，还要稀释模型注意力。skill 天生就是渐进披露的。

所以合理的架构分工是：**MCP 是手脚，skill 是神经**。复杂 MCP 前面必须站一个轻量 skill 做导航，在 skill 文档里写死"执行本技能时先唤醒哪几个底层工具"。

### 第四步：规则明明写了，为什么没拦住

最刺痛的反思在这里。我有一份八条的工作纪律，第一条就是"先出方案，禁止闷头就改"。事后看，模型违规时并不觉得自己在违规——它真心以为写脚本是捷径。

训诫式规则依赖"读到时能理解、执行时能想起、想起时能对号"。三层里任何一层松动，规则就形同虚设。这不是态度问题，是机制问题：**没有任何确定性检查点拦截这条路径**。

顺带把 Claude Code 的两个文件层级也验明白了：`CLAUDE.md` 在系统注入时带着"覆盖一切默认行为"的契约，宪法级，每轮常驻；`MEMORY.md` 被明确标注为"背景上下文，不是指令"。两者冲突时前者直接否决后者。这个权重结构决定了治理方案该往哪放。

### 第五步：外面的人怎么解这个问题

去 GitHub 上转了一圈，同一个坑里已经站了不少人：

- 有项目做了 MCP 代理，用 4 个工具换掉上百个 schema——先模糊搜（返回工具名加一句话介绍，正好补上缺失的 L2），再看单个工具的 Schema，再代理执行，号称省 85% 到 96% 的上下文；
- 学术线（Gorilla、ToolLLM 那一路）把工具检索做成 RAG：用户提问先过一遍向量或 BM25，只把最相关的三五个工具拼进当轮请求；
- 还有人把扁平工具列表组织成树状命名空间，先选域，再下发域内工具。

思路各异，共性就一条：**不指望模型自己想起来**。

## 药方：三层映射矩阵

照抄的部分来了。我最后落的是一套三层结构，核心思想是把"查工具"从模型的自觉行为变成确定性路由：

**第一层，必读层，放进 CLAUDE.md。** 一张十二行的精简表，意图域到工具的硬映射：逆向类任务必走逆向 skill 再唤醒逆向 MCP；修 bug 走代码图谱 MCP；文档生成走文档 skill。这张表每轮都在上下文里，宪法级权重，不依赖任何主动查询。表尾附一句话自查：本任务命中的意图域，对应 skill 调了吗？

**第二层，权威维护层，放进知识库。** 全量意图域（含低频任务）、每个 MCP 的领域图谱、关键工具名。第一层没覆盖的意图，先来这里查。用户提过一个尖锐的问题：表放知识库里你不看怎么办？答案就是分层——高频条目根本不进知识库，直接进宪法层；知识库只承接维护职责。

**第三层，跨会话记忆。** 存一份 MCP 实例到领域到工具名的快查图谱，加一条维护纪律：新增或退役任何 skill 和 MCP，前两层同步改。

还有一条专门堵子代理的漏洞：派发任务给子代理时，prompt 里必须显式继承对应 skill 的工作规程。不然主代理以为子代理会用工具，子代理以为主代理给的就是全部——我那一个上午，就是这两层互相指望，最后谁也没指望上。

## 本质

一句话：**延迟加载省下来的每一个 token，都得用确定性路由还回去——省在说明书上，就要花在路标上；指望模型自觉，等于没省。**
